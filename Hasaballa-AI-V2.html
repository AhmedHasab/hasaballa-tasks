What we are asking the development team to build

HASABALLA already aims to produce dramatized documentaries, crime reconstructions, disappearances, espionage, horror, historical events and biographies. V2 should let the same creator also explain evidence with animated graphics, build children's stories, bring imaginative objects to life, move characters between virtual locations, and transfer a precise performance to another character.

No duplicate development: use the existing image, voice, Character Pack, video generation, Smart Director and Timeline capabilities wherever appropriate. BIE keeps a character's recurring behavioral identity; the new Performance Transfer Studio copies a specific recorded performance.
01Existing roadmap · Task 19First priority

Hasaballa Engine

The smart learning core of the entire platform

Think of this as the system that notices what works, records useful feedback and gradually helps HASABALLA improve. It is not a separate video-making tool. Its job is to strengthen the tools already inside the platform.

ENGINELocal feedback · evaluation · learning

In real life

You correct a character's facial consistency, reject a weak animation or improve the pacing of a scene. The Engine records those decisions and, after evaluation, helps future outputs avoid the same mistakes—rather than making you repeat your preferences every time.

Original Task 19 intent

A future shadow learning core watching text, image, voice and animation workflows; potential future specialist models: Hasaballa Text, ImageGen, Animator and Voice. The original page proposed starting this work after roughly six months of usage.

Build requirements
  • Collect structured, local quality signals from each native module.
  • Capture user-approved corrections, ratings and failed generations.
  • Maintain a versioned, auditable local training dataset.
  • Separate feedback collection from actual model training.
  • Support controlled evaluations before any model replacement.
  • Integrate with all seven priorities and existing production tools.

Acceptance test

Generate a scene, correct a documented fault, and verify that the Engine logs the feedback locally with traceable provenance. Show a repeatable evaluation before claiming that a later model has improved. The original 90–95% replacement-quality goal is a target to measure, not a result already achieved.

02Existing roadmap · Task 20Second priority

Auto Smart Fix

Find problems before the viewer does

A dedicated post-generation inspector. It should catch common visual and textual mistakes, explain each one in plain language, and offer a controlled fix instead of forcing the user to regenerate the whole scene.

◈ Scene quality review3 issues found

Broken frames / integrity checkPassed

In real life

An evidence-board scene contains a misspelled Arabic street name. Auto Smart Fix identifies the affected frame, suggests the correction, and lets you apply or reject it without changing the rest of the video.

Where it belongs

After image/video generation and before the existing Selective Smart Edit (Task 11). It should cooperate with the Hasaballa Engine's quality feedback, but remain usable as an independent inspection tool.

Build requirements
  • Find Arabic and English text errors on signs, papers and captions.
  • Compare character identity against reference images.
  • Detect lighting, color and saturation inconsistencies.
  • Flag distortions, glitches and visually broken elements.
  • Show exact timecodes, frames and issue explanations.
  • Provide Fix / Ignore / Review Again with safe undo.

Acceptance test

Introduce four known faults in a short test scene: a misspelled Arabic word, the wrong face, a light mismatch and a distorted object. The system must identify the affected timecodes and support an isolated correction that does not damage approved content.

03New integrated studio

Motion Graphics Studio

Make information come alive on screen

Animated writing, glowing labels, arrows, evidence boxes, hand-drawn lines, maps, paths, charts and explanatory sequences—not static pictures that merely slide across a video.

Visual reference: map and explanatory graphics from a user-provided video

In real life

In a disappearance story, a map draws the victim's last confirmed route, reveals each verified timestamp, then highlights the point where the trail ends. For an espionage episode, names, arrows and connections build an investigation board live.

Three creative modes

  1. Kinetic Typography — writing appears word by word or stroke by stroke.
  2. Animated Drawing — draw arrows, lines, circles and maps.
  3. Data Graphics — timelines, evidence cards, maps and charts.
Build requirements
  • Editable Arabic/English text with correct RTL shaping.
  • Write-on, draw-on, type-on and erase animations.
  • Vector boxes, paths, arrows, shapes and connectors.
  • Keyframes, easing, timing and per-layer opacity.
  • Attach labels to tracked objects in the video frame.
  • Save presets and export sharp 4K graphics where supported.

Acceptance test

Create a 30-second investigation map from text. The editor must preserve each label, stroke and animation as individually editable Timeline objects. Change an Arabic name and its animation timing without regenerating the entire video.

04New integrated studio

Cartoon & 3D Animation Studio

Children's stories, illustrated characters and animated explainers

Build recurring cartoon actors and complete short animations. 2D is flat illustration, 2.5D adds simulated depth, and 3D uses volumetric characters and environments. “AI character” describes how a character is produced, not its visual style.

Visual reference: expressive illustrated character from the supplied clips

In real life

Create a series about a curious child exploring Egyptian history. Across different episodes, their face, costume and voice remain recognizable, while the story, location, expressions and actions change.

What the director controls

Character creation, style (2D / 2.5D / 3D), expressions, rigs, acting, dialogue, lip sync, camera angles, props, backgrounds and scene-to-scene continuity—without rebuilding the same character every time.

Build requirements
  • Persistent cartoon Character Packs and style sheets.
  • Facial rigs, poses, body animation and gestures.
  • Multi-character scenes and real-time dialogue timing.
  • Optional 2D, 2.5D and 3D production pipelines.
  • Storyboards, scene templates and reusable backgrounds.
  • Correct dialogue lip sync and editable Timeline layers.

Acceptance test

Produce three connected scenes with the same animated child: walking, speaking and reacting to another character. Change the camera and environment without unexpected identity, costume or style drift.

05New integrated studio

Living Objects Studio

Give animals, places, objects and natural elements a personality

Anthropomorphic animation: not simply sticking eyes onto an object, but designing a believable character from its original form. A talking sea should still feel fluid; a talking tree should still move like wood and leaves.

Visual reference: a humanized conceptual character from the supplied clips

In real life

Let a historic house narrate its past, a banknote explain its journey, or the sea express anger during a fictional storm. This can serve children's education, satire, symbolic stories and atmospheric horror.

More than a talking face

The engine must adapt eyes, mouth, hands, posture, emotion and motion to the thing being animated—trees, oceans, currency, animals, landmarks or fictional concepts.

Build requirements
  • Humanize objects while retaining their original silhouette.
  • Entity-specific face placement and expression control.
  • Emotion, voice, dialogue and lip synchronization.
  • Object-appropriate physics and motion behavior.
  • Consistent identities over multiple scenes or episodes.
  • Use shared character tooling without duplicating BIE.

Acceptance test

Create a talking tree and a talking wave in three emotional states each. Both must speak, react and move naturally without losing their tree/water identity; save and reuse each character in another scene.

06New integrated studio

Virtual Worlds & VFX Studio

Move a character anywhere—without filming yourself in a studio

Use filmed actors or entirely generated characters inside virtual locations. Replace a location, change wardrobe, match lighting and perspective, and keep the scene believable. The goal is more than changing a flat background.

Visual reference: composited environments in the supplied Abdullah Al-Sharif clips

In real life

For an espionage story, the same virtual actor moves from an old railway station to an interrogation room and then to a busy foreign street. Clothing and lighting change as required, but the underlying character remains recognizably the same.

Three production modes

  1. Footage of a real actor → virtual location.
  2. Generated actor → generated virtual world.
  3. Existing scene → new surroundings and wardrobe.
Build requirements
  • Subject segmentation and foreground-background compositing.
  • Camera tracking and matched virtual camera movement.
  • Relighting, shadows, depth and subject occlusion.
  • Wardrobe/style edits with identity lock and preview.
  • Environmental effects, scale and perspective matching.
  • Native Timeline control and honest 4K delivery labeling.

Acceptance test

Place one actor in three convincingly different scenes with moving camera, matching shadows, appropriate object occlusion and changed outfits. Validate 4K output and explicitly distinguish native 4K renders from upscaled results.

07New integrated studioSeparate from BIE

Advanced Performance Transfer Studio

Copy a specific performance—not a person's permanent behavior

Give the system a source performance video and a target character. Make the target reproduce the source's gesture timing, dance, head movement, expressions and spoken/sung performance as faithfully as the selected model allows, while protecting the target's visual identity.

Visual reference: expressive character performance; not proof of a particular transfer method

In real life

Take an original fictional character and make it act out a reference dancer's specific sequence: every step, hand gesture, pause, smile and head turn should follow the source timing. The character keeps its own face and outfit.

Five controllable channels

  1. Body: posture, walk, dance, hands and feet.
  2. Face: gaze, eyebrows, expression and head motion.
  3. Speech: cadence, pauses and delivery.
  4. Singing: timing, expression and performance.
  5. Mix: different approved sources for different channels.
Build requirements
  • Import a source performance video and target Character Pack.
  • Separate body motion, facial performance and audio tracks.
  • Retarget movements across different body proportions.
  • Sync lips to the selected spoken or sung audio track.
  • Support selective transfer, blending and per-scene overrides.
  • Keep target appearance stable; show timing/drift previews.

Acceptance test

Give the same original character two different reference performances: a short dance and a spoken dramatic scene. Transfer each independently, retain the target identity and outfit, preserve timing and expressions, and permit separate edits to body, face and audio. A simple face swap or generic lip sync does not pass.

Critical architectural boundary

BIE and Performance Transfer are not the same feature

Both can use motion analysis, facial tracking and video generation. Their purpose, stored data and expected output are different. The development team should reuse compatible technical services, not charge for two copies of the same identity system.

🧠 BIE · Behavioral Identity Engine

🎭 Performance Transfer Studio

Who is this character, behaviorally?

Extracts repeatable mannerisms from behavioral reference footage: habitual eye movements, smiles, gestures, posture, timing, reactions and speech rhythm. Saves a reusable Motion Profile in a Character Pack.

Example: a historical figure keeps recognizable gestures across ten newly generated scenes.

Ownership: the pre-existing separate BIE scope; not delivered again as V2 Performance Transfer.

What should this character perform right now?

Takes an explicit, scene-specific performance reference and retargets its sequence and timing to a different target character. It may intentionally override the target's usual mannerisms for that one shot.

Example: an original fictional character precisely performs a particular reference dance.

Ownership: new V2 Studio; do not recreate BIE's permanent behavior profile system.

Rules for combining them
BIE is the character's default behaviorTransfer may override behavior for one sceneAfter the shot, the BIE profile remains intactOne shared Character PackNo duplicated model integration fees

The BIE proposal also contemplated non-human characters, but the engineering response scoped the first implementation to humans. Living Objects must not silently assume that a production-ready non-human BIE already exists.

Non-negotiable engineering contract

Everything must be native to HASABALLA AI

The seven priorities must become internal modules in the same product. No website launch buttons, cloud subscriptions, external credits or hidden API dependence. This is a future acceptance requirement, not a declaration that current local models already meet every target.

01 · One coherent workflow

Available from Smart Director Auto, Smart Director Manual and dedicated tools. Every output returns to the same project and Timeline with consistent save, undo and preview behavior.

02 · Real editable layers

Text, vectors, camera moves, character tracks, voice, reference performances and effects remain editable wherever technically possible. Do not flatten everything unnecessarily.

03 · Fully offline by design

All runtime inference, media processing and data storage must work on the user's Windows 11 workstation without cloud connectivity or paid APIs. Verify model licenses and memory use individually.

04 · Shared internal services

Reuse Character Packs, asset library, model scheduling, lip sync, rendering, audio processing, animation and Smart Director orchestration. Explicit BIE/Transfer separation prevents duplicate development.

05 · Quality, speed and truthfulness

Target cinematic output and 4K workflows; measure actual render quality, latency and GPU/VRAM usage. Record whether a result is native 4K or upscaled. Do not promise model equivalence without tests.

06 · Evidence-ready delivery

Require actual working demos, source code, local install instructions and reproducible acceptance tests for every module. No placeholder interfaces or links to unrelated hosted products.

Shared end-to-end acceptance scenario

Create a short mystery story in Smart Director, draw an animated route on a map, introduce a recurring cartoon character, let a talking object explain a clue, place an actor inside a virtual scene, transfer one approved dance performance, then run Auto Smart Fix. Every asset must stay in the same editable project, with no internet connection.
